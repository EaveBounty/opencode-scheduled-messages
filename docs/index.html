TL;DR: opencode-scheduled-messages appends a prompt to an existing OpenCode V2 session at a chosen time, or creates one when asked. It is a separate Node.js process on the public HTTP API: not an OpenCode plugin, it does not fork OpenCode, and it is single-user. In short, a timer for the conversation you already have.

一句话：opencode-scheduled-messages 会在你选定的时间，把一条 prompt 追加到已有的 OpenCode V2 会话里；需要时也可以新建会话。它是独立运行的 Node.js 进程，走公开 HTTP API：不是 OpenCode 插件，不 fork OpenCode，且只服务单个用户。简单说，它就是给现有对话加的一个定时器。

Install from npm Source on GitHub Deployment guide

What it is

A timer, a SQLite queue and a mobile PWA for OpenCode V2, packed into one Node process with zero runtime dependencies.

Who it is for

One person running OpenCode on a laptop or home server who thinks in a long thread and wants a sentence delivered later, off-peak, or after the current turn.

What it replaces

The manual workaround: staying awake, a shell sleep that loses the thread, or a scheduler that starts a fresh session for every job.

Core difference

The message is appended to the session you already have, through POST /api/session/{id}/prompt, not sent into a new empty context.

Why the timer has to live outside OpenCode为什么定时器必须放在 OpenCode 之外

OpenCode V2 keeps a durable inbox, but a queued item does not wake itself. Its plugin surface cannot register HTTP routes or own a timer that survives a restart, and a setTimeout in a browser tab dies when the phone sleeps. An OS cron entry can start a fresh session, yet the sentence you wanted to add belongs to the thread you were already thinking in.

This project stores {sessionID, text, dueAt, timezone, policies} in SQLite, claims due rows atomically every 10 seconds, and calls the public prompt endpoint with a client-generated msg_ id. Retries reuse that id, and OpenCode returns the original message for a duplicate, so a retry cannot send the sentence twice.

The useful primitive is not “run an agent on a schedule”. It is “deliver this thought to the conversation that already exists, at the time I chose”.

OpenCode V2 有持久收件箱，但队列里的条目不会自己醒来。它的插件接口既无法注册 HTTP 路由，也无法持有能跨重启存活的定时器；浏览器标签页里的 setTimeout 会在手机休眠时失效。系统 cron 能启动一个新会话，可你想补上的那句话，属于你原本就在思考的那个线程。

本项目把 {sessionID, text, dueAt, timezone, policies} 存进 SQLite，每 10 秒原子地领取到期的行，并带着客户端生成的 msg_ id 调用公开的 prompt 接口。重试复用同一个 id，OpenCode 对重复 id 返回原消息，所以重试不会把同一句话发两遍。

真正有用的原语不是“按计划跑一个 agent”，而是“在我选定的时间，把这个想法送到已经存在的对话里”。

Install and schedule the first message安装并安排第一条消息

You need Node.js 22.6 or newer and a running OpenCode V2 server. On first start the scheduler prints an initial password once; sign in with it, then change it in Settings (it is stored as a scrypt hash). The browser never receives the OpenCode password, because the gateway injects Basic auth server-side.

# 1. Start OpenCode's HTTP API if it is not already running
opencode serve --service

# 2. Start the scheduler (prints the initial password once)
npx opencode-scheduled-messages

# 3. Open the PWA, sign in with the initial password,
#    pick a session and a time
#    http://127.0.0.1:8788

On a phone in the same Wi-Fi, run ocsched --lan and open the printed LAN address. For an installable HTTPS PWA, put Tailscale or Cloudflare Tunnel in front:

tailscale serve --bg --https=443 http://127.0.0.1:8788
tailscale serve --bg --https=8443 http://127.0.0.1:4096
# then set Settings → OpenCode native URL to
# https://<host>.<tailnet>.ts.net:8443

The PWA is mobile-first: 44 px targets, iOS safe areas, a bottom composer and dark/light tokens. “Open full session” hands off to OpenCode's own UI for tool output, diffs and images, so this project does not need to reimplement a Markdown renderer.

需要 Node.js 22.6 或更高版本，以及一个正在运行的 OpenCode V2 服务。首次启动时，调度器会只打印一次初始密码；用它登录后，在 Settings 里改成你自己的密码（以 scrypt 哈希保存）。浏览器永远拿不到你的 OpenCode 密码，因为网关在服务端注入 Basic 认证。

What happens when the machine, the session, or the network is not ready机器、会话或网络没准备好时会发生什么

  • Session busy. By default the scheduler waits for idle, re-checks every 30 seconds for up to 30 minutes, then marks the schedule missed. You can choose steer (inject into the current turn) or skip per schedule.
  • OpenCode offline. The row stays pending and retries. After a restart it sends only inside the 120-minute grace window; later than that it becomes missed and waits for a manual resend, so a stale idea does not fire at noon.
  • Unattended permission request. The default is to wait for you. Auto-reject, read-only auto-approve and allow-all are opt-in per schedule; allow-all is labelled dangerous because it is.
  • “Sent” is not “finished”. A 200 response means OpenCode accepted the prompt into its inbox. Execution progress is visible in the native session or over SSE; the queue marks the delivery, not the model's completion.
  • 会话忙碌。默认等到空闲，每 30 秒复查一次、最多等 30 分钟，然后把该计划标记为 missed。每条计划也可以单独选 steer（注入当前回合）或 skip（跳过）。
  • OpenCode 离线。该行保持 pending 并重试。重启后只在 120 分钟宽限窗口内发送；更晚就变成 missed，等你手动重发，避免过期的想法在中午突然触发。
  • 无人值守的权限请求。默认等你处理。自动拒绝、只读自动批准、全部放行都需要按计划显式开启；全部放行被标为危险，因为它确实危险。
  • “已送达”不等于“已完成”。HTTP 200 只表示 OpenCode 把 prompt 收进了收件箱。执行进度在原生会话或 SSE 里看；队列标记的是投递，不是模型跑完。

Where the alternatives are better

  • opencode-scheduler keeps the deployment surface to one process: it runs as a plugin inside OpenCode, with no second daemon, no extra port and no separate login to manage. If a new session per run is acceptable, that is simpler.
  • opencode-manager covers a broader dashboard: many projects, richer session management and a container-first install. If you want one place to manage everything, it does more than this page's single job.
  • Both are better choices for recurring scheduled runs or multi-user access. Version 0.1 here is one-shot and single-user on purpose; if you need a team service, this is the wrong tool.

替代品更好的地方

  • opencode-scheduler 把部署面压缩到一个进程：它作为插件跑在 OpenCode 里面，不需要第二个守护进程、不需要额外端口、也不需要多管一套登录。如果每次运行新建会话可以接受，它更简单。
  • opencode-manager 覆盖更宽的仪表盘：多项目、更丰富的会话管理、容器优先的安装方式。如果你想要一个地方管所有东西，它做的不止这一页的单一任务。
  • 两者都更适合周期性计划任务或多用户访问。这里的 0.1 刻意做成一次性、单用户；如果你需要团队服务，这个工具就是错的。

DeepSeek's official API charges half price during off-peak hours. Peak hours are 01:00–04:00 and 06:00–10:00 UTC, Monday to Friday, excluding Chinese public holidays; everything else is off-peak. In Beijing time that is 09:00–12:00 and 14:00–18:00 on weekdays. The peak token price is exactly 2× the off-peak price, so the same tokens cost 50% less off-peak. Source: DeepSeek API pricing.

If you use opencode-go, you pay a subscription rather than per token, but the monthly allowance is denominated in dollars: off-peak therefore halves the allowance consumed, not the subscription price. The UI says “谷时 · 半额消耗”, not “save 50%”, because that distinction matters.

DeepSeek 官方 API 在谷时收一半价钱。峰时是 UTC 周一至周五 01:00–04:00 和 06:00–10:00，中国法定节假日除外；其余时间都是谷时。换成北京时间，就是工作日的 09:00–12:00 和 14:00–18:00。峰时单价正好是谷时的 2 倍，所以同样的 token 在谷时便宜 50%。来源：DeepSeek API 价格页。

输入框会提示你选的时间属于峰时还是谷时。如果你用 opencode-go，付的是订阅费而不是按 token 计费，但每月额度以美元计价：谷时省下的是额度消耗，不是订阅价格。所以界面写“谷时 · 半额消耗”，而不是“省 50%”——这个区别很重要。

  • Not an OpenCode plugin. OpenCode V2 plugins cannot register HTTP routes or own a durable timer, so the scheduler is a separate process using the public API.
  • Does not fork OpenCode. No browser automation, no injected scripts, no changes to the native web UI or its database.
  • Single-user. One gateway, one OpenCode instance, one login password. There are no accounts, roles or tenant isolation.

FAQ: questions people actually type常见问题：中文用户真实会搜的问法

Does OpenCode support scheduled messages or cron out of the box?

No. OpenCode V2.1 has a durable inbox, but a queued item does not wake itself, so there is no timer. This project adds the timer in a separate Node process and leaves OpenCode itself unchanged.

How do I send a message to an existing OpenCode session later?

Pick the session in the PWA, write the prompt and choose a time. At T-0 the gateway calls POST /api/session/{id}/prompt with a client-generated msg_ id, so the text is appended to that thread instead of opening a new one. Retries reuse the same id.

What happens if my laptop is asleep or OpenCode is offline at the scheduled time?

The row stays pending and the gateway retries while OpenCode is unreachable. After a restart it sends only inside the 120-minute grace window; later than that the schedule becomes missed and waits for a manual resend, so a stale idea does not fire at noon.

What if the target session is busy when the message is due?

The default policy waits for idle, re-checking every 30 seconds for up to 30 minutes, then marks the schedule missed. You can choose steer to inject into the current turn, or skip, per schedule.

Does it work with DeepSeek off-peak pricing?

Yes, and the composer shows whether the chosen time is peak or off-peak using the official UTC windows. On a pay-as-you-go DeepSeek key the off-peak token price is half the peak price, because peak costs 2×. On opencode-go, off-peak halves the allowance consumed, not the subscription price.

Is this an OpenCode plugin? Do I have to modify OpenCode?

No. It is a separate process that speaks the public HTTP API: it is not a plugin, it does not fork OpenCode, and it injects nothing into the native UI. Plugins cannot register HTTP routes or own a durable timer, which is why the scheduler lives outside.

Can I use it from my phone?

Yes. On the same Wi-Fi run ocsched --lan; for an installable HTTPS PWA put Tailscale or Cloudflare Tunnel in front. The PWA is mobile-first, and one tap opens OpenCode's own session UI for the full transcript, diffs and images.

Is there a recurring or cron-style schedule?

Not in 0.1. Schedules are one-shot by design: the use case is this thought, in this thread, tonight. Recurring jobs would spend tokens unattended, so the data model leaves room but the feature is deliberately absent.

How do I log in the first time, and what if I lose the password?

On first start the terminal prints the initial password once; that string is the login credential. Sign in, then change it in Settings, where it is stored as a scrypt hash. If you lose it, reset the credential in the data directory and restart; OpenCode itself is untouched.

How much memory and disk does it use?

A 0.1.0 instance measured 70–110 MB RSS with one SSE connection and peaked near 150 MB; the generated systemd unit caps memory at 192 MB soft and 320 MB hard. The SQLite file lives under ~/.local/share and uses WAL.

OpenCode 能定时发消息吗？

原生不能。OpenCode V2.1 只有持久收件箱，没有定时器；这个项目用独立的 Node 进程每 10 秒检查一次队列，到点再调用官方 HTTP API，不修改 OpenCode 本身。

怎么给已有的 OpenCode 会话发消息，而不是新建会话？

在 PWA 里选中目标会话，写入内容并选择时间；到点后调用 POST /api/session/{id}/prompt 追加到该会话。新建会话是可选模式，不是默认行为，所以上下文不会丢。

电脑关机或休眠了，到点的消息还会发吗？

会尝试补发，但只在 120 分钟宽限内；超过宽限会标记为 missed，等你在界面上手动重发，避免半夜的旧想法在第二天中午突然执行。

到了发送时间，目标会话还在跑怎么办？

默认策略是等它空闲：每 30 秒复查一次，最多等 30 分钟，仍不空闲就标记为 missed。每条计划也可以改选 steer（注入当前回合）或 skip（直接跳过）。

DeepSeek 错峰真的能省钱吗？

按 token 计费时能，谷时单价正好是峰时的一半，峰时是 2 倍。官方峰时为 UTC 周一至周五 01:00–04:00 与 06:00–10:00（北京时间 09:00–12:00、14:00–18:00），中国法定节假日除外，详见官方价格页。opencode-go 订阅只减少额度消耗，不降低月费。

它是 OpenCode 插件吗？需要改 OpenCode 吗？

不是插件，也不 fork OpenCode。它不注入脚本、不改原生界面，只作为单用户进程调用公开 API；一个网关、一个 OpenCode 实例、一个登录密码。

手机上怎么用？一定要装 Tailscale 吗？

不一定要。同一 Wi-Fi 下运行 ocsched --lan 就能打开局域网地址；要安装 PWA 或走 HTTPS，再把 Tailscale 或 Cloudflare Tunnel 放在前面。Tailscale 只是推荐路径，不是运行依赖。

支持循环任务（cron）吗？

0.1 不支持，只有一次性定时。循环任务会在无人看守时持续消耗 token，因此被刻意留到后续版本，而不是做成一个默认开启的开关。

第一次登录的密码是什么？忘了怎么办？

首次启动时终端只打印一次初始密码，那串就是登录凭据；登录后在 Settings 里改成自己的密码，服务端以 scrypt 哈希保存，明文不落盘。忘记后可以在数据目录里重置凭据再重启，不需要改 OpenCode。

它占用多少内存和磁盘？

0.1.0 实测空闲时 RSS 70–110 MB，在一条 SSE 连接下峰值接近 150 MB；生成的 systemd 单元把内存限制在软 192 MB、硬 320 MB。SQLite 文件在 ~/.local/share 下，使用 WAL 模式。
